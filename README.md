# fixhub-diag

A small Node.js diagnostic tool for the [iFixit FixHub Power Station](https://www.ifixit.com/fixhub), built on top of the [FixHub serial CLI](https://github.com/iFixit/FixHub/blob/main/README.md).

It connects over serial, runs a fixed set of **read-only** commands, and prints each response cleanly (one command → one response, no interleaving).

## Why this exists

Built while troubleshooting a power station whose front port stopped recognizing a connected iron (LED D4 stuck solid). The interesting finding, in case it saves someone else time: `usbpd summary`, `usbpd status`, and `toolcomms` all returned **identical values regardless of what was actually plugged into TOOLPORT1/TOOLPORT2** — including with nothing connected to either port at all. That pointed at the port-state reporting itself being stuck/stale rather than a firmware or iron-side issue, and firmware reflashing across three versions (1.0.0, 1.4.3, 1.5.0) didn't change it.

If you're chasing a similar "front port won't recognize the iron" issue, it's worth running this a few times under different physical states (nothing plugged in / iron in Port 1 / iron in Port 2) and comparing the raw numbers rather than trusting a single run.

## Usage

```bash
npm install
node fixhub-diag.js --list                 # find the power station's serial port
node fixhub-diag.js <port> [baudRate]       # run diagnostics (baudRate defaults to 115200)
```

Examples:

```bash
node fixhub-diag.js /dev/tty.usbmodemXXXX
node fixhub-diag.js COM5
```

## What it runs

| Command | Why |
|---|---|
| `version` | Confirms which firmware is actually running |
| `hwid get` | Board revision — useful context for a support ticket |
| `pwrsrc get` | What the board thinks is currently powering it |
| `uptime` | Time since last reset |
| `toolcomms` | Active-tool status per front port (0 = none, 1 = active) |
| `comms g0version` | Asks the second MCU for its firmware version; a timeout means it's not responding on the inter-MCU bus |
| `usbpd summary` | Quick state/power view for TOOLPORT1, TOOLPORT2, and REAR |
| `usbpd status` | Detailed per-port USB-PD negotiation state |
| `errorlog` | Read-only — prints the log, does **not** run `errorlog clear` |

Everything here is read-only against the device. Commands that write or reset state (`gpio write`, `nvm_programming`, `rt9490` writes, `errorlog clear`, etc.) are intentionally left out.

## Notes

- Requires the [`serialport`](https://www.npmjs.com/package/serialport) package (installed via `npm install`).
- Waits for the actual shell prompt (`ifixitl5:~$`) to reappear before considering a response complete, rather than guessing on a silence timeout — this matters because the device can be slower to respond than a fixed timeout expects, which otherwise causes one response to bleed into the next command's output.
- Not affiliated with iFixit. Command set is based on their [public README](https://github.com/iFixit/FixHub/blob/main/README.md).
